# ADR-024 — Durable activities checkpoint model calls by logical slot

## Status

Accepted.

## Context

KAIRO's replay-safe model gateway originally assumed one paid model call per Temporal activity. The latest model-call heartbeat was sufficient because there was only one logical provider outcome to recover.

Autonomous research needs at least two distinct model operations in one durable activity: planning and evidence-bound synthesis. If each call writes a standalone heartbeat, the second call erases the persisted checkpoint of the first. A retry could then pay for planning again or, worse, encounter an ambiguous provider outcome without enough durable state to decide safely.

## Decision

A multi-call activity constructs one `ModelCheckpointLedger` at activity start. The ledger is restored from Temporal heartbeat details and stores one normal KAIRO model-call checkpoint per stable idempotency key.

Every stage transition rewrites one heartbeat envelope containing all known slots. The first research version uses two deterministic logical slots:

- `research-plan-v1`
- `research-synthesize-v1`

The existing single-call checkpoint contract remains supported for older and simpler activities. A legacy single checkpoint can be promoted into the ledger on retry.

Each slot keeps the existing fail-closed semantics independently:

- `started` with no known response means the provider outcome may be ambiguous, so blind replay is refused;
- `completed` or `accounting` with a persisted result can safely resume canonical usage accounting;
- `accounted` can return the persisted completion without a provider call.

The research model budget remains a single parent Task budget. Planning and synthesis each authorize against half of the configured estimated model budget; actual canonical usage continues to be deduplicated by model-call idempotency key.

Research synthesis receives only canonical child tool results. Every structured finding must cite one or more exact `ToolInvocation.id` values from the supplied evidence bundle. A citation outside that set is invalid model output and the activity fails rather than publishing an unsupported claim.

## Consequences

- Later model calls cannot erase earlier replay checkpoints within the same activity.
- A retry can independently recover planning and synthesis without double-paying for a known model outcome.
- The ledger is reusable by future multi-turn agents without making the model provider or Langfuse canonical state.
- Research reports retain machine-verifiable provenance back to canonical MCP invocations.
- Large arbitrary tool results are compacted before synthesis; canonical raw results remain stored separately and are not replaced by the compact prompt representation.

## Rejected alternatives

### Keep only the latest model heartbeat

Rejected because the latest slot would erase prior paid-call recovery state.

### Store checkpoint state only in Worker memory

Rejected because Worker memory disappears on crash and cannot support Temporal replay.

### Trust synthesis citations generated by the model

Rejected because model-generated identifiers are proposals, not provenance. KAIRO validates them against the canonical evidence bundle before accepting the report.
